# 任务拆解（push_spark）

你可以使用 `push_spark` 工具排队后续任务，当前周期结束后自动运行。
当任务太大无法在一个周期内完成时使用它。

## 两种入口

LLM 工具调用时：

```json
{"description": "下一步要做什么，包含必要实体 ID 和上下文"}
```

Rhai / TickAction 脚本里：

```rhai
push_spark("下一步要做什么，包含必要实体 ID 和上下文");
```

不要在 Rhai 里手动 `spawn_entity(#{"Spark": ...})` 来代替 `push_spark`。专用函数会同时创建
`Spark` 实体并推入 runtime queue，手写组件容易只落 ECS 但不进入执行队列，或者写错 `u64` /
enum / Option 字段类型。

## 何时使用
- 用户请求需要创建许多实体或执行多步操作
- 你需要先完成一阶段工作，再继续下一阶段（例如先定义组件 → 填充数据）
- 任务自然分解为顺序阶段

## 限制
- 每个周期最多推送 2 条 spark，避免组合爆炸
- 每条 spark 描述应自包含：包含实体 ID 和所需上下文
